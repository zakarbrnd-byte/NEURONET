# Experiment 0.6D — Synapse Birth and Pruning

**Status:** Implemented · Conclusion pending longer campaigns  
**Version marker:** Synapse Birth and Pruning · Version 0.6D

---

## Hypothesis

If growth candidates mature under sustained coactivation and pruning risk accumulates over multiple evaluations, the tissue can change its wiring diagram deterministically without randomness or frontend-forced edits.

---

## Creation threshold

A candidate may birth a synapse only when all hold:

| Condition | Default |
| --- | --- |
| Status | `maturing` |
| Readiness | ≥ `0.90` (`creation_readiness_threshold`) |
| Maturation hold | `candidate_maturation_ticks + creation_hold_evals` (= 4 evals) |
| Reach / distance | within configured max and morphology reach |
| No duplicate / self | enforced |
| Topology | under max total / out / in degree limits |

Initial weight: **8.0 mV**  
ID: monotonic `SYNAPSE-0006`, `SYNAPSE-0007`, …  
`eligible_from_tick = creation_tick + 1`

---

## Maturation requirement

Candidates must remain above coactivation threshold across consecutive structural evaluations to enter and hold `maturing`. Evidence collapse resets maturation.

---

## Pruning requirement

A synapse may be pruned only when all hold:

| Condition | Default |
| --- | --- |
| Status | `atRisk` |
| Risk | ≥ `0.70` |
| Inactivity | ≥ 12 ticks |
| Low weight duration | ≥ 4 evals |
| Low health duration | ≥ 4 evals |
| Sustained at-risk evals | ≥ 2 |
| Grace expired | age ≥ 10 |
| Not structurally protected | explicit flag |
| Min topology | remaining ≥ 3 synapses |
| Demo path | at least one path `NEURON-001 → NEURON-005` remains |

One bad tick never deletes a synapse.

---

## Grace period

Newly created and young synapses are `protected` until age ≥ `pruning_grace_ticks` (10).

---

## Protected initial synapses

| Synapse | Reason |
| --- | --- |
| `SYNAPSE-001` | `backbone_input_pathway` — primary observatory cascade entry |
| `SYNAPSE-002` | `backbone_cascade` — continues demonstration pathway |

`SYNAPSE-003`, `SYNAPSE-004`, and `SYNAPSE-005` are not permanently protected and may prune after sustained evidence if constraints allow.

---

## Topology limits

- min total synapses: 3  
- max total synapses: 12  
- max outgoing / incoming per neuron: 3  
- preserve demo path: true  

---

## Mutation timing semantics

Recommended tick order (implemented):

1. Firing  
2. Propagation (only synapses with `tick ≥ eligible_from_tick`)  
3. Recovery / synaptic plasticity  
4. Coactivation update  
5. Structural evaluation (interval)  
6. Plan mutations (no in-place vector edits while iterating)  
7. Validate + commit births then prunes in stable ID order  
8. Emit structured events  
9. Return snapshot  

**Birth:** available beginning next tick.  
**Prune:** may have already propagated this tick; removed afterward.

---

## Test protocol

1. Reset tissue.  
2. Force or grow a mature `NEURON-002 → NEURON-001` candidate; confirm `SYNAPSE-0006` birth.  
3. Confirm no same-tick delivery from the new synapse.  
4. Idle / weaken an unprotected synapse past sustained thresholds; confirm prune or block with reason codes.  
5. Reset; confirm five synapses and ID counter 6.

---

## Observed result

Local unit/integration tests confirm deterministic birth IDs, next-tick activation, sustained pruning, protection, topology bounds, and reset. Public confirmation requires deploy of 0.6D.

---

## Limitations

- Educational model — not biological morphogenesis  
- No neuron birth/death or migration  
- No random growth, genetics, body, memory, or cognition  
- Demo path constraint is a minimal transparent rule, not a graph optimizer
