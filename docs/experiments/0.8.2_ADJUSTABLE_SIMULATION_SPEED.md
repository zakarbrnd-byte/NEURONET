# Experiment 0.8.2 — Adjustable Simulation Speed

Simulation-control and observability patch. Not a new scientific milestone.

## Tick definition

A **tick** is one complete logical backend simulation step.

A tick is **not** one real-world second, one biological millisecond, or one
action-potential duration.

Simulation speed controls only how quickly Mission Control requests and displays
confirmed backend steps.

Fixed inter-request delay: **800 ms** (`DEFAULT_STEP_DELAY_MS`).

## Speed presets (UI pacing targets)

| Preset | Delay after confirmed step | Render mode |
| --- | --- | --- |
| 0.5× Observe | ~1600 ms | Full |
| 1× Normal (default) | ~800 ms | Full |
| 2× Fast | ~400 ms | Full |
| 5× Development | ~160 ms | Short |
| 10× Long Run | ~80 ms | Sampled |
| Max | 0 ms (+ `setTimeout(0)` yield) | Summary |

Actual throughput is limited by network latency, Render response time, and device
performance. Observer Status shows **Actual ticks/s** from confirmed responses
and **Backend latency** measured around each `POST /api/network/step`.

## Request ownership

- Frontend selects pacing only.
- Backend remains source of truth for every tick.
- No local intermediate neural computation.
- No skipped ticks.
- No overlapping step requests.
- Speed may change while Running; the new delay applies after the in-flight step.

## Batch stepping

**Not required / not implemented** for 0.8.2.

Sequential single-tick requests are adequate for Max mode on the public API.
Every biological tick still executes exactly once on the backend.

## Render modes

| Mode | Speeds | Behavior |
| --- | --- | --- |
| Full | 0.5×–2× | Per-signal travel animations |
| Short | 5× | Short / reduced travel emphasis |
| Sampled | 10× | Snapshot refresh ~several times/s; no travel animation |
| Summary | Max | Bounded snapshot refresh (~4–10/s); no per-signal animation |

Important timeline events (firing, sensory, plasticity, birth/pruning, development)
are still recorded from confirmed backend responses at every speed.

Reduced-motion preferences continue to suppress decorative motion.

## Determinism acceptance

Experiment A: Reset → Balanced → exactly 300 ticks at 1× pacing.  
Experiment B: Reset → same config → exactly 300 ticks at Max pacing.

Because both paths issue the same sequence of single-tick backend steps, biological
snapshots must match (tick, neurons, synapses, candidates, environment counters,
deterministic IDs). Wall-clock TPS and render state may differ.

Verified locally against backend 0.8.1: two identical 300-step sequential runs
produced matching biological hashes (tick 300, 6 synapses, 1 birth). UI speed
cannot alter backend state — only inter-request wall-clock delay.

## Persistence

Selected speed is stored in `localStorage` key `neuronet.simulationSpeed`.
Reload restores the speed selection and remains **Paused** (does not auto-Run).
Backend biological state is never persisted in localStorage.

## Mobile

Speed control sits in the quick-action bar with ≥44px touch targets.
Mission Control remains `viewport-locked` / `100dvh` layout.

## Limitations

- Actual Max TPS is dominated by HTTP round-trip to Render.
- Sampled/Summary modes may visually lag the latest tick by one refresh interval.
- Frontend and backend version strings may differ; both are displayed.
